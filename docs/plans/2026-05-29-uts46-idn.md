# UTS-46 IDN support

**Goal:** Take IDN handling from "Punycode-decode + `lowercased()`" to spec-grade
UTS-46, so that any representation of a domain (A-label / U-label, any
normalization, any mapped form) looks up consistently and compares equal. Keep
the official PSL conformance suite green; add Unicode's `IdnaTestV2.txt` as the
UTS-46 correctness backbone.

## Current state (baseline)

- `NormalizedHost` lowercases via `String.lowercased()`, splits on `.`, and
  Punycode-**decodes** `xn--` labels into a parallel `matchLabels`. Output is
  rebuilt from `originalLabels` (input form preserved).
- Matching compares `matchLabels` against verbatim Unicode-form rules. Swift
  `String ==` is canonical-equivalence-aware, so NFC vs NFD already matches.
- **The real gap:** output/comparison use `originalLabels`, so the same domain
  in A-label vs U-label form is *not* equal —
  `haveSameRegistrableDomain("食狮.公司.cn", "xn--85x722f.xn--55qx5d.cn")` is
  `false`. There is no Punycode encoder, no UTS-46 mapping table, no validity.

## Resolved decisions

- **Processing profile:** UTS-46 **nontransitional** (`Transitional_Processing
  = false`), matching modern browsers / WHATWG URL. **`UseSTD3ASCIIRules =
  false`** — the WHATWG/browser default, and the disposition the bundled Unicode
  17 mapping table encodes (it contains no `disallowed_STD3_*` entries).
  `VerifyDnsLength` is applied in the strict `toASCII` only. **`CheckBidi` / `CheckJoiners` are OUT OF SCOPE (P4)** — registration
  validity, not needed to find a registrable domain; documented as deferred.
- **Two-layer architecture:**
  1. A standalone, spec-faithful `IDNA` processor (`toASCII` / `toUnicode`) that
     reports errors and is tested directly against `IdnaTestV2.txt`.
  2. The PSL `lookup` path *uses* the processor leniently for canonicalization,
     and stays non-throwing. `lookup` keeps returning a `HostInfo` for any
     splittable host; it does not start rejecting hosts on UTS-46 errors (no
     behavior regression). Strict validation is the processor's job, exposed
     separately.
- **Output policy (keeps PSL suite green):** the existing display fields
  (`publicSuffix`, `registrableDomain`, `subdomain`) keep preserving the
  caller's input form. UTS-46 results are exposed as **new canonical fields**,
  not by changing existing output.
- **API additions on `HostInfo`:**
  - `canonicalRegistrableDomain: String?` — U-label, NFC, UTS-46-mapped,
    lowercased. The comparison/storage key.
  - `canonicalPublicSuffix: String` — same normalization.
  - `asciiRegistrableDomain: String?` — A-label form (from P3 ToASCII).
  - `haveSameRegistrableDomain` compares `canonicalRegistrableDomain`.
- **Mapping table:** generated from Unicode `IdnaMappingTable.txt` by
  `script/UpdateIDNAMapping.swift` (mirrors `UpdatePSL.swift`), bundled as a
  compact binary resource parsed by an internal loader. Not codegen'd Swift
  (avoids compile bloat). Pinned Unicode version recorded in the resource header.
- **NFC:** Foundation `precomposedStringWithCanonicalMapping` (cross-platform on
  iOS/macOS/Linux/Windows). No ICU dependency anywhere.

## Phases

### P0 — Canonical comparison (no data tables) — the bug fix

- Build a canonical key per label from `matchLabels` (already decoded): NFC +
  `lowercased()` (UTS-46 mapping arrives in P2; this is correct for the cases the
  PSL covers today).
- Add `HostInfo.canonicalRegistrableDomain` / `canonicalPublicSuffix`, rebuilt
  from canonical labels. `lookup` populates them.
- `haveSameRegistrableDomain` compares `canonicalRegistrableDomain`.
- Tests: A-label ≡ U-label equivalence (食狮 vs xn--85x722f, mixed forms);
  existing display behavior and PSL conformance unchanged.
- Commit: `feat: canonicalize IDN registrable-domain comparison (A-label = U-label)`

### P2 — UTS-46 mapping table + mapping step

- `script/UpdateIDNAMapping.swift`: fetch `IdnaMappingTable.txt`, emit compact
  ranges `(start, end, status, mapping)`; write bundled resource + version header.
- Internal `IDNAMapping` loader + `IDNA.map(_:)` (mapped/ignored/disallowed/
  deviation, nontransitional, UseSTD3).
- Replace `lowercased()` in the canonicalization path with full mapping + NFC.
- Commits: `build(script): generate UTS-46 IDNA mapping table`,
  `feat: UTS-46 mapping + NFC in IDN normalization`

### P3 — Punycode encode, ToASCII, conformance suite

- `Punycode.encode` mirroring the existing decoder.
- `IDNA.toASCII` / `IDNA.toUnicode` with the decode→re-encode round-trip check
  for `xn--` inputs; populate `HostInfo.asciiRegistrableDomain`.
- Vendor `IdnaTestV2.txt` → parameterized conformance suite (like
  `test_psl.txt`).
- Update `IDNHandling.docc` + `CHANGELOG.md` (Added: UTS-46 processing,
  canonical/ASCII fields; note Bidi/Joiners deferred).
- Commits: `feat: RFC 3492 Punycode encoder`,
  `feat: UTS-46 toASCII/toUnicode with round-trip validation`,
  `test: IdnaTestV2 conformance suite`, `docs: document UTS-46 IDN support`

## Out of scope (P4, future)

Bidi rule (RFC 5893), ContextJ/ContextO joiner checks, DNS-length verification,
and a public host-*validation* API. Track separately if registration-grade
validation is ever wanted.

## Testing bar

- `IdnaTestV2.txt` parameterized suite green (the definition of "great UTS-46").
- A-label ≡ U-label equivalence across `lookup` / `haveSameRegistrableDomain`.
- Existing PSL `test_psl.txt` suite stays green (form-preserving output intact).
